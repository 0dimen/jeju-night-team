# CCTV 선택 근거와 다음 작업

2026년 11월 18일 · 사용자 요청에 따라 생활방범 우선 선택을 적용

## 결론

**생활방범용 CCTV를 우선 사용하는 방향으로 선택했습니다.** 다른 목적은 자동으로 섞지 않습니다. 설치 목적을 고르는 설정과 자료를 읽는 코드를 분리했으므로, 나중에 포함 목적을 바꿔도 분류·긴급 안내·제보 저장 코드는 수정할 필요가 없습니다. 계산 결과와 보고서는 다시 확인해야 합니다.

이번 선택은 목적 범위에 대한 결정입니다. 자료 이용 조건·좌표계 확인이나 실제 서비스 공개가 승인된 것은 아닙니다.

## 선택 근거와 대안

| 선택지 | 장점 | 한계와 현재 처리 |
|---|---|---|
| **생활방범 우선 — 선택** | 보행 주변 시설의 위치를 설명하려는 목적과 가장 가까움 | 현재 원본에는 8행뿐. 과거 자료라 현재 작동·촬영 범위는 알 수 없음 |
| 어린이보호용 추가 | 후보 지점 100행이 더 있음 | 보행로 주변인지와 목적 적합성을 확인한 뒤 별도 판단. 지금은 제외 |
| 교통단속용 포함 | 348행으로 수가 많음 | 차량 단속을 보행 방범의 근거로 섞으면 설명이 부정확해짐. 기본 제외 |
| 전체 479행 포함 | 전처리가 간단하고 표시 지점이 많음 | 설치 목적이 다른 시설을 같은 의미로 취급하게 되어 제외 |
| 최신 생활방범 자료 추가 확보 | 시점과 지역 범위를 보강할 수 있음 | 확보 가능성과 이용 조건 확인이 필요. 자동 채택하지 않음 |

이것은 설치 목적에 근거한 서비스 설계 판단이며 방범 효과를 실증한 결과가 아닙니다.

## 실제로 처리한 결과

- 원본 479행을 그대로 보존하고 생활방범 8행을 내부 전처리 파일로 분리했습니다.
- 8행의 기재 카메라 대수 합계는 37입니다. 37개 독립 위치나 현재 작동 대수를 뜻하지 않습니다.
- **8행 모두 서귀포시 주소이며 기준일은 2022년 12월 15일입니다.** 전체 원본의 최신 날짜인 2024년을 이 부분 자료의 기준일로 쓰면 안 됩니다.
- 서로 100미터 이내인 쌍은 2쌍이며 거리는 약 3.8미터·13.5미터입니다. 같은 시설인지 확인하지 않았으므로 병합하지 않았습니다. 100미터는 분포 확인용이며 경로 계산 기본 반경 50미터와 별도입니다.
- 이 자료만으로 제주시의 기존 예시 경로를 실제 비교할 수는 없습니다. 서귀포의 좁은 지역에서 실제 보행 경로를 확보하거나 자료를 보강해야 합니다. 시연 지역은 아직 새로 확정하지 않았습니다.
- 이용 조건·좌표계 확인 표시가 없으므로 실제 경로 계산 사용 가능 상태는 ‘아직 아님’으로 남겼습니다. 기본 합성 시연에 실제 점을 섞지 않았습니다.

## 바로 할 수 있는 다른 일

1. **실행 준비:** 센터에서 기본 점검 명령을 실행하면 설치 실패 여부를 먼저 확인할 수 있습니다. 명령과 Linux 결과는 이미 준비했습니다. 센터 접근은 필요합니다.
2. **문장 처리:** 예비 실행에서 발견한 시각 표현·부정 문장·복수 시설의 처리 개선을 준비할 수 있습니다. 수희의 문장과 의도 확인을 받으면 수정 전후를 비교합니다. 이번 자료 선택 작업으로 정답을 대신 확정하지 않습니다.
3. **실제 경로 연결 준비:** 정해진 지역의 보행 경로 파일을 읽는 연결부와 누락·잘못된 좌표 검사를 만들 수 있습니다. 길을 직접 확보·확인하기 전에는 실제 경로 결과라고 표시하지 않습니다.
4. **제출 정리:** 실행 방법·자료 기준일·가상/실제 구분을 문서에 반영하고 최종 묶음을 별도로 만들 수 있습니다. 기존 제출 ZIP은 이전 시점의 검토본으로 보존합니다.

## 왜 이전 계획은 몇 시간으로 잡았나

앞서 적은 6~9시간은 **CCTV 목적을 고르는 데 걸리는 시간이 아니라**, 자료 이용·좌표 확인, 실제 보행 경로 확보, 거리 계산 연결, 오류 검사와 실행 기록을 포함한 전체 작업량의 추정이었습니다. 선택 작업과 전체 연결 시간을 분리해서 설명하지 못했습니다.

목적별 분리와 설정 구현은 이번 작업에서 끝냈습니다. 이것만을 위해 몇 시간 더 기다릴 이유는 없습니다. 남은 시간은 다음 조건에 따라 달라집니다.

| 남은 일 | 시간이 달라지는 이유 | 끝났다고 볼 기준 |
|---|---|---|
| 이용 조건·좌표계 확인 | 자료 설명이나 제공처 확인을 기다릴 수 있음 | 어떤 조건·좌표계로 사용할지 근거가 남음 |
| 실제 보행 경로 확보 | 두 경로가 실제로 걸을 수 있는 연결인지 확인 필요 | 같은 출발·도착의 실제 보행 경로와 출처가 있음 |
| 계산·응답 연결 | 단위·자료 없음·중복·버전 처리를 확인해야 함 | 실제 입력과 결과를 대조하고 검사가 통과함 |
| 센터 실행 | 해당 컴퓨터 접근·설치 가능 여부에 달림 | 그 컴퓨터에서 실행한 결과가 남음 |

현재 남은 작업의 완료 시각은 실측하지 않았습니다. 위 확인을 코드 작성 시간과 구분해 보고하고, 확보가 어려우면 자료·지역 대안을 제시하겠습니다.

## 재현과 변경 방법

- 목적 설정: config/cctv_selection.yaml. `include_purposes`만 바꾸면 선택 범위가 바뀝니다. 다른 승인 표시를 임의로 바꾸지 않습니다.
- 전처리 실행: `.venv/bin/python scripts/prepare_selected_cctv.py`.
- 요약 근거: data/processed/cctv_selection_check.json. 입력과 선택 설정의 파일 지문을 남깁니다.
- 좌표가 있는 전처리 파일은 data/raw/ 안에 보관하며 커밋·검토 ZIP에서 제외합니다.
- 원본을 바꾸지 않았고, 이번 선택을 되돌리려면 목적 설정을 변경한 뒤 다시 전처리하면 됩니다. 실제 계산에 사용한 뒤에는 재계산도 필요합니다.
