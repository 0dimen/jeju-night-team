# 입력 평가와 확인 질문 보완

## 결론

**출처 질문·예약 실행 요청·모호한 제보의 분기를 보완했습니다.** 기존 분류 후보를 사람 정답으로 확정하지 않고, 제보는 저장 전에 확인 질문을 보여 주도록 연결했습니다. 바뀐 동작은 새 페이지 대화 API를 기준으로 확인했습니다.

## 입력과 전후 관찰

합성8개와 사용자가 전달한3개 사례를 구분해 실행했습니다. 시간·위치를 포함한 문맥은 합성 좌표만 썼습니다. 사람의 의미 판정 칸은 비워 두었으며 정확도나 실제 사용자 성공률을 산출하지 않았습니다.

| 입력 상황 | 이전 응답 | 보완 후 응답 |
|---|---|---|
| ‘CCTV 정보는 어디서 가져왔고 언제 조사?’ | 지원 범위 안내 | 출처·확인하지 못한 자료 한계 안내 |
| 경로 대화 중 ‘가로등 정보가 언제 조사?’ | 출발 날짜 질문 | 시간을 묻지 않고 자료 안내 |
| 항공권·택시를 예약해 달라는 명령 | 경로의 위치·시간 질문 | 예약 실행은 지원하지 않는다고 안내 |
| ‘고장은 아니고 쓰레기가 있어요’ | 위치 질문 | 부정 표현의 의미 확인, 저장 안 함 |
| ‘CCTV와 가로등이 모두 고장’ | 위치 질문 | 처리할 시설 확인, 저장 안 함 |
| ‘CCTV가 어두워요’ | 지원 범위 안내 | 영상인지 주변 길인지 확인, 저장 안 함 |
| ‘누가 따라와요’와 예약 요청이 섞임 | 긴급 안내 | 긴급 안내 유지, 위치 상태 비움 |

예약을 언급했다는 이유만으로 길 질문을 막지는 않습니다. ‘호텔을 예약해뒀어요. 걸어가는 길 알려줘’ 같은 경우는 경로 요청으로 유지합니다.

사용자 사례인 학교 두 곳 비교·대학에서 집·‘3시’ 답변도 같은 관찰에 남겼습니다. 학교 두 곳의 실제 좌표와 다른 목적지 비교는 여전히 미구현입니다. 집 위치를 먼저 확인하고, ‘3시’는 날짜와 오전·오후가 없으면 확인하는 기존 정책을 유지했습니다.

## 적용 범위와 남은 한계

- `agent/intent/`에서 명시적인 정보 출처 표현과 예약 실행 명령을 구분합니다.
- `agent/conversation.py`에서 제보를 저장 없는 미리보기로 보냅니다. 무관한 출처 질문·예약 요청·제보에는 기존 페이지 위치를 붙여 보내지 않습니다.
- 미리보기는 `needs_clarification`으로 질문이 있음을 명시합니다. 자동 분류 후보의 시설·문제 값이 사람에게 승인된 것은 아닙니다.
- 기존 `/agent/chat`의 제보 저장 흐름과 분류 계약은 바꾸지 않았습니다. 모든 제보 접수 화면은 미리보기 확인 단계를 연결해야 합니다.
- 문장 분기는 제한된 표현 규칙입니다. 문장 전체의 부정 범위나 모든 복수 문제를 이해한다고 보지 않습니다. 한 문장의 모든 시설을 자동 분리 저장하지 않습니다.
- 명령 표현과 자료 출처 표현의 뜻은 사람이 추가 사례로 확인해야 합니다. 예비 입력에서 동작이 달라졌다는 사실만으로 일반 정확도가 높아졌다고 결론 내리지 않습니다.

## 검사와 근거

새 회귀 검사6개를 포함한 경로 입력 보완까지 포함한 현재 Python 전체236개 검사 통과. 부정·복수 제보가 DB에 저장되지 않는지, 무관한 위치 상태를 되돌리지 않는지, 긴급 우선과 예약 언급의 반례를 확인했습니다. 모델 호출과 실제 개인정보 사용은 없습니다.

입력과 전후 응답 요약: `tests/fixtures/input_routing_observations.json`. 판정은 기술적 분기·저장 상태의 관찰이며 사람 의미 정답은 모두 미승인입니다. 코드 변경 후 같은 입력을 다시 사용한 검사로, 새로운 독립 검증 집합이라고 보지 않습니다.

새 가상환경에서도 requirements-test.txt만 설치한 뒤 키를 제거하고 네트워크 연결을 차단해 전체236개 검사를 통과했습니다. 모델 가중치 설치와 실제 사용자 개인정보 사용은 없습니다.
