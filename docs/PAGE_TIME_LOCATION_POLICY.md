# 날짜·오전·오후 확인과 페이지 안의 집 위치

2026년 11월 18일 사용자 결정 반영

## 결론

**시간이 필요한 요청은 날짜와 오전·오후를 확인합니다. 집 위치는 현재 페이지의 메모리에서만 사용하고 페이지를 떠나면 지웁니다.** 출처 질문·제보·긴급 요청 등 출발 시각이 필요 없는 답변은 시간을 묻기 위해 막지 않습니다.

## 구현한 범위

- 새 API `POST /agent/conversation`이 `text`와 `state`를 받습니다.
- 날짜·시간·오전/오후가 빠졌으면 하나씩 물어봅니다. 현재 시각에서 날짜나 오후를 추정하지 않습니다.
- 집을 포함한 목적 위치를 먼저 확인하고 출발 위치를 확인합니다. 장소 좌표를 이름만으로 만들어 넣지 않습니다.
- 예시: 위치 두 개가 있는 상태에서 ‘3시’ → 날짜 질문 → ‘2026-11-19’ → 오전/오후 질문 → ‘오후’ → `2026-11-19T15:00` 요청 준비.
- 시각을 바꾸면 이전 출발 시각을 지워 오래된 값으로 계산하지 않습니다.
- 출처 질문은 출발 시각 없이 기존 안내를 바로 돌려줍니다. 긴급 안내는 다른 상태보다 우선하며 위치 상태를 돌려주지 않습니다.
- 서버 세션 저장소·집 위치 DB·원문 대화 기록을 만들지 않습니다. 페이지 상태는 요청을 처리하는 동안만 사용하고 응답으로 돌려줍니다.
- 응답은 `Cache-Control: no-store`로 캐시하지 않도록 표시합니다.
- `route_ready`는 필요한 정보가 모였다는 뜻입니다. 실제 길찾기·시설 계산 완료가 아닙니다. 기존 `/agent/chat`·제보 저장 흐름과 별도입니다.

## 화면 담당이 반드시 연결할 부분

현재 저장소에는 실제 서비스 페이지가 없으므로 **페이지를 떠나는 동작 자체는 아직 검사하지 못했습니다.** 화면 연결 시 아래를 적용해야 사용자 요구가 끝까지 충족됩니다.

1. `state`는 그 페이지의 변수에만 둡니다. localStorage·sessionStorage·쿠키·URL·공통 전역 저장소에 집 위치를 넣지 않습니다.
2. 페이지 이동·종료·새로고침 때 상태를 지웁니다. 단일 페이지 앱의 화면 이동과 브라우저 뒤로가기 복원도 포함합니다.
3. 이동 중인 요청은 중단하고 늦게 도착한 응답이 지운 상태를 되살리지 못하게 합니다.
4. 새로 들어온 페이지는 빈 `state`로 시작합니다. 사용자가 저장 버튼을 누르지 않아도 이전 집 위치를 자동 복구하지 않습니다.
5. 요청·응답 본문을 분석 도구나 오류 로그에 넣지 않습니다. 실제 위치를 무료 AI에 전송하지 않습니다.

서버가 상태를 보관하지 않더라도 화면이 이전 응답을 저장해 재전송하면 위치가 다시 전달됩니다. 따라서 서버 검사 통과를 페이지 종료 후 삭제 완료로 표시하지 않습니다.

## 요청 형식

```json
{"text":"3시에 갈거야","state":{"awaiting_route":true,"request":{"origin":{"name":"SYNTHETIC 출발","lat":33.5,"lng":126.5},"destination":{"name":"SYNTHETIC 도착","lat":33.51,"lng":126.51}}}}
```

응답의 `state`를 같은 페이지의 다음 요청에만 보냅니다. 위치 예시는 가상이며 실제 집 주소가 아닙니다. 날짜는 현재 YYYY-MM-DD와 명시적인 오전/오후 또는 24시간 표기를 지원합니다. ‘내일’ 등 상대 날짜·학교별 지도 검색은 아직 지원하지 않습니다.

## 검사와 남은 일

현재 자동 검사는 날짜·오전/오후 확인, 자정·정오 변환, 날짜 오류, 이전 시각 수정, 새 빈 상태의 집 위치 미상속, 무관한 출처 질문, 긴급 우선, DB 미저장과 응답 캐시 금지를 확인합니다. 브라우저의 페이지 이동·복원·요청 중단 검사는 실제 화면 연결 후 필요합니다.

시간대 5개 이름의 경계나 점수 가중치는 이번 결정에 포함하지 않았습니다. 이전 문서의 현재 시각을 통한 오후 추정 제안은 이 사용자 결정으로 대체합니다.
