# 실제 CCTV API 연결 결과

## 결론

저장한 `DATA_GO_KR_SERVICE_KEY`로 공식 CCTV API 인증과 조회가 성공했습니다. 확인한 제주특별자치도·제주시·서귀포시 기관코드의 전체 페이지를 받아 **1,043행**을 확보했습니다. 그중 **생활방범71행·기재248대·서로 다른 좌표69쌍**입니다. 같은 좌표의2행은 자동 병합하지 않았습니다.

기존 파일의 생활방범8행·기재37대보다 공개 자료가 늘었지만 생활방범은 여전히 모두 서귀포입니다. 이 수치를 제주 전체 실제 설치대수나 현재 작동 대수로 보지 않습니다. 기본 앱은 합성 시연을 유지하며 새 자료를 자동 채택하지 않았습니다.

제주시 반환362행은 모두 교통단속입니다. 서귀포의 생활방범71행도 설치 장소·촬영방면과 공개 도로 관련성을 확인해야 합니다. 시설물관리504행을 방범용으로 바꾸지 않았습니다. 기존479행과 새1,043행은 버전·범위가 달라 단순히 더하지 않습니다.

## 조회 조건 확인

처음 ‘제주’ 도로명주소 검색에는 다른 지역의 ‘제주횟집’, ‘국제주유소’ 같은 이름도 포함됐습니다. 해당391행을 제주 자료로 세지 않았습니다. 정확한 도 이름으로 주소 범위를 확인한 뒤 국가기록원의 공식 기관코드와 반환된 기관코드를 대조하고 기관별 전체 페이지를 수집했습니다.

도로명주소 조건만 쓰면 누락이 있습니다. 새 서귀포681행 중292행, 생활방범71행 중36행은 도로명주소가 비어 있어 기관코드 조회로 보완했습니다. 각 기관의 제공 총수와 받은 페이지 합계가 일치하고, 기관 불일치·페이지 간 중복 관리번호가 없음을 확인했습니다. 원본1,043행의 위경도는 유한 숫자와 제주 거친 범위 검사에 통과했지만 위치 정밀도·현재 설치 여부를 검증한 것은 아닙니다.

## 재실행

서버의 비밀 환경변수를 불러온 뒤 수집 도구를 수동 실행합니다. 키 값을 명령 인자로 쓰지 않습니다.

```bash
.venv/bin/python scripts/fetch_public_cctv.py \
  --output /tmp/cctv-research-cache \
  --agency 6500000 --agency 6510000 --agency 6520000
```

인증키는 서버 환경변수 `DATA_GO_KR_SERVICE_KEY`로 읽습니다. 배포 후에도 같은 이름의 비밀 환경변수를 사용합니다. 프론트 입력·응답에 키를 전달하지 않습니다. 캐시는 응답만 저장하며 인증키·요청 전체URL은 저장하지 않습니다. 원본·캐시·실제 키를Git에 올리지 않습니다. 기존 캐시가 있으면 재호출하지 않으며, 최신판을 받을 때는 새 출력 폴더를 지정합니다.

수집은1초 간격·페이지당100행·기관별최대30페이지로 제한했습니다. 인증 실패·기관 불일치·중복 관리번호·전체 행수 변화·빈 중간 페이지·최대 페이지 초과를 완료로 처리하지 않습니다. API오류에 요청URL·인증키가 포함되지 않도록 일반 오류로 변환합니다. 인터넷을 사용하는 수집 도구이며 기본 앱이 실행될 때 자동 호출하지 않습니다.

## 검증과 남은 일

API는HTTP200·정상 결과코드로 응답했습니다. 독립 연결 코드로 실제100행 재조회와 제공총수681도 확인했습니다. 저장된 기관별12페이지를 재생해 다시1,043행을 확인했습니다. 전체 Python263개 통과(4.75초, 의존성 경고1개). 기관·중복 거부, 빈 정상응답, 인증 실패, 키를 포함한 오류·응답의 가림 검사를 포함합니다. 이것은 자료의 의미·촬영 범위·작동 확인이나 사용자 채택 승인이 아닙니다.

다음에는 생활방범71행의 공개 도로 적합성·기준일·좌표 정밀도와 기존8행의 관계를 비교한 뒤 실제 시연용 입력을 준비합니다. 제주시 방범 자료 부족은 별도 원본 확인이 필요합니다. 데이터의 일간 갱신 설명과 개별 행의 과거 기준일을 혼동하지 않습니다.
