## 팀원이 직접 고칠 때 (수희·혜수)

**기준 브랜치는 `feature/service-screens`입니다.** 이 브랜치가 실서비스(https://jeju-night-team.vercel.app)와 같습니다. `night/integrate`는 밤 자동 작업용이라 기준으로 쓰지 않습니다. main은 제출 기록용이며 팀원 1명의 승인이 있어야 합쳐집니다.

1. GitHub 저장소에서 브랜치 선택을 `feature/service-screens`로 바꾼 뒤, 새 브랜치 `fix/이름-내용`을 만듭니다(예: `fix/suhee-report-text`).
2. 고칩니다. 문구·문서는 GitHub 웹 편집기(파일 열기 → 연필 아이콘)로 고쳐도 됩니다. 코드는 내려받아 README의 설치 명령 후 `.venv/bin/python -m pytest -q`가 통과하는지 확인합니다.
3. 브랜치를 올리면 Vercel이 **미리보기 주소**를 만듭니다. GitHub 커밋 옆 Vercel 표시를 눌러 바뀐 화면을 확인합니다(실서비스는 그대로입니다).
4. `feature/service-screens`로 PR을 만들고, 무엇을 왜 고쳤는지와 확인한 화면을 적습니다.
5. 채원이 확인한 뒤 병합합니다. **병합하면 실서비스에 바로 반영됩니다.**

하지 말 것: `feature/service-screens`·main에 직접 올리기, 강제 덮어쓰기(force push), 키·개인정보 커밋, 화면에 지어낸 숫자 넣기.

급한 문구 하나만 고칠 때도 1→4 순서는 같습니다(웹 편집기에서 '새 브랜치로 커밋하고 PR 만들기'를 고르면 한 번에 됩니다). 충돌 표시가 나오거나 검사가 실패하면 고치지 말고 PR에 그대로 둔 채 채원에게 알려 주세요. 06:00까지 밤 작업이 같은 파일을 고치고 있어서, 그 전에 만든 PR은 채원이 합칠 순서를 정합니다.
