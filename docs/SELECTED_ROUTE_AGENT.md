# 장소 선택과 공개 구간 대화 연결

## 결론

이제 두 고정 구간 외에도 **제주 장소·주소를 검색하고 결과를 선택해 실제 보행 후보를 비교**할 수 있습니다. 검색과 경로 API는 서버에서 연결하며, 선택한 위치는 해당 페이지에서만 유지합니다. 공개 구간 대화에는 TMAP·공개 도로망 선택을 추가했습니다.

## 사용할 순서

### 장소·주소를 선택하는 방법

1. `/app` → 지도 → ‘장소를 선택해서 실제 길 찾기’를 엽니다.
2. 장소명·도로명·지번 중 검색 방식을 고릅니다.
3. 출발지와 도착지를 각각 검색하고, **주소를 확인한 뒤 결과 버튼을 선택**합니다. 첫 결과를 자동으로 선택하지 않습니다.
4. 한국 시간 기준의 출발 날짜와 24시간 시각, 우선 조건을 입력합니다.
5. 선택 좌표를 TMAP으로 보내 경로를 비교합니다. 같은 형상은 하나로 합칩니다.
6. 결과에서 VWorld 버튼을 누르면 배경지도·경로·주변 공개 시설을 표시합니다.

검색 방식이나 검색어가 바뀌면 그 위치를 다시 선택해야 합니다. 대학·공원처럼 넓은 장소는 대표점과 보행 입구가 다를 수 있으므로 더 구체적인 출입구·도로명 주소가 필요할 수 있습니다. 현재 선택은 검색 결과의 지점을 고르는 방식이며, 지도 클릭으로 지점을 옮기거나 GPS를 쓰는 기능은 아직 없습니다.

직선 5m~20km의 제주 좌표를 지원합니다. 이 거리는 현재 연구 기능의 연산·실험 범위이며 안전 기준이나 도보 권장 거리가 아닙니다. 출발지·도착지·날짜·시각을 확인해도 신호·폐쇄·시간별 밝기를 실측한 것은 아닙니다.

### 공개 구간을 대화로 고르는 방법

`연동 공개 구간을 티맵으로 CCTV 위주로 3시에 갈게요` → 날짜 질문에 `2026-11-20` → 오전/오후 질문에 `오후`로 답합니다. TMAP 보행 후보를 계산합니다. `공개 도로망으로 변경해줘`라고 하면 기존 시설 선호 도로망 탐색으로 돌아갑니다. `티맵으로 변경해줘`도 지원합니다.

이 대화는 공개 두 구간용입니다. 임의 장소는 위 검색·선택 폼을 사용합니다. 문장 속 집 주소나 장소를 자동 검색·확정하거나 서로 다른 두 목적지를 한 번에 비교하지 않습니다. 상대 날짜를 임의로 확정하지 않고 필요한 날짜를 확인합니다.

## 위치가 남지 않도록 처리한 범위

- 장소 검색어·선택 좌표·경로는 앱 서버의 파일·데이터베이스·캐시에 저장하지 않습니다. 출발·도착 명칭도 TMAP에 전달하지 않고 일반 표기로 보냅니다.
- 페이지 이동·종료·새로고침·초기화 시 선택 위치·검색 결과·입력을 지웁니다. localStorage·sessionStorage를 사용하지 않습니다.
- 검색어는 VWorld에 POST 본문으로, 좌표는 TMAP에 POST 본문으로 전달합니다. 사용자 입력을 URL 쿼리에 넣지 않습니다.
- 선택 위치의 배경지도 타일도 POST로 요청해 타일 번호를 브라우저 요청 URL에 남기지 않습니다. 키는 브라우저에 전달하지 않습니다.
- 지도 로딩 중 페이지를 떠나면 요청을 취소하고, 만든 임시 이미지 주소를 해제합니다. 시간이나 위치가 바뀐 뒤 늦게 도착한 결과도 다시 표시하지 않습니다.
- 고정 공개 구간만 기존 한 시간 캐시를 씁니다. 선택한 임의 좌표는 이를 사용하지 않습니다. 외부 제공사의 수신·로그 처리 정책까지 앱에서 지울 수 있다는 뜻은 아닙니다.

공유 장치에서 브라우저 자체 기록·개발자 도구·외부 제공사의 기록을 모두 지워 준다고 주장하지 않습니다. 앱이 직접 관리하는 위치 상태와 저장소의 범위입니다.

## 자료와 계산

원본에서 선택한 제주시 52,014행·서귀포 37,919행, 합계 **조명 89,933행**을 사용합니다. 표준 CCTV는 네 목적 937행, 과거 대체 원본은 473행이며 서로 합치지 않습니다. 행은 공개 위치 목록이고 실제 기기 대수를 뜻하지 않습니다.

배포 생성기는 기존 두 구간 자료 4개에 제주 시설 좌표 자료 1개를 추가합니다. 합계 약 **4.27MB**, 원본 CSV·원본의 주소·기타 열은 실행물에 넣지 않습니다. 원본과 파생 자료의 시설 좌표·출처·선택 행수 일치를 검사했습니다. 자료가 없거나 잘못되면 0%나 합성 자료로 대신하지 않습니다.

거리·시간은 TMAP 제공값, 시설 인접 비율은 반환 형상에서 별도로 계산한 값입니다. 겹치는 시설 반경은 중복 합산하지 않습니다. 공간 격자로 주변 시설만 찾아 계산을 줄이되 같은 원 합집합 길이 식을 사용합니다. 우회 한도·반경·가중치는 기존 연구 설정이며 새로운 사용자 선호 기준을 확정하지 않았습니다.

현재 비교에 시민 제보를 자동 반영하지 않습니다. 제보 검증·게시·실제 시설 상태 변경 연결은 별도 작업입니다.

## API와 배포 담당 인수

| 경로 | 역할 |
|---|---|
| `POST /maps/places/search` | 검색어와 검색 방식을 받아 후보 반환, 기록·결과 캐시 없음 |
| `POST /research/routes/selected` | 선택 좌표·날짜·시각·선호 조건의 일회성 경로 비교 |
| `POST /maps/vworld/tile` | 선택 위치 배경지도 중계, URL에 타일 번호 없음 |
| `POST /research/agent/conversation` | 공개 구간 대화, TMAP·공개 도로망 선택 |

서버에 `VWORLD_API_KEY`·`TMAP_APP_KEY`를 설정합니다. `VWORLD_DOMAIN`은 발급 조건상 필요할 때 실제 등록 도메인으로 설정합니다. 비밀키를 코드·Git에 넣지 않습니다.

Vercel은 기존 `app.py` 진입점과 `vercel.json`을 사용합니다. 빌드 시 `scripts/build_vercel_data.py`를 다시 실행해 제주 시설 자료까지 생성해야 합니다. 공개 원본이 없는 CLI 업로드는 로컬에서 먼저 자료를 생성합니다. 원본이 빠진 실행 폴더에서 화면·공개 계산·시설 연결·선택 요청 실패 처리를 별도 확인합니다. 실제 Vercel 빌드·공개 접속 검증은 배포 담당이 이어서 해야 합니다.

원본이 빠지고 실행용 계산 자료가 포함된 ZIP도 만들 수 있습니다.

```bash
.venv/bin/python scripts/build_runtime_archive.py --output /tmp/jeju-preview.zip --include-facility-data
```

이 명령은 커밋된 코드와 지정한 공개 계산 자료만 묶습니다. 기존 출력 파일은 덮어쓰지 않습니다. 옵션을 빼면 기존처럼 코드만 묶으므로 별도 데이터 연결이 필요합니다.

## 검증과 한계

기준은 사용자 결정의 날짜·오전/오후 확인, 페이지 한정 위치, 규칙·문장 틀 기본 구성과 네 CCTV 목적입니다. 선택한 위치는 재질문 없이 다른 공개 지점으로 바꾸지 않아야 하며, 자료가 없으면 실패를 안내하고 서버에 선택 경로를 남기지 않아야 합니다. 이는 사람의 의미 평가를 자동 승인하는 기준이 아닙니다.

- Python **306개 통과**, 의존성 경고 1개. POST 검색·키 비노출·지역 필터·실패 격리, 자연어 TMAP 선택, 선택 요청 캐시·제보 저장 없음, 잘못된 날짜·거리 거부, 격자 계산의 손계산 45/150m 일치, 원본과 제주 파생 자료 일치를 검사했습니다.
- 공개 장소를 이용한 실제 Chromium: 장소 검색→사용자 선택→TMAP→VWorld 지도 연결을 확인했습니다. 배포용 자료만 사용하고 원본 입력 경로는 연결하지 않았습니다. 선택 경로 캐시 파일 추가 0, 검색어 URL 노출 0, 키 브라우저 노출 0, 직접 외부 요청 0, JavaScript 오류 0입니다.
- 320/390/430 폭에서 가로 넘침 없음. 시간 수정 후 이전 응답 폐기, 검색 오류 입력 유지, 화면 이동·새로고침 삭제를 확인했습니다.
- 장소명·도로명·지번의 세 검색 방식 모두 공개 지점으로 실제 응답을 확인했습니다. 개인 집 주소를 실험에 사용하지 않았습니다.
- 실제 사용자 문장 전체의 의미 정확도, 현장 통행, 계단·장벽·보도, 로드뷰 최신성, 센터 실기기와 운영 도메인은 별도 확인입니다.
