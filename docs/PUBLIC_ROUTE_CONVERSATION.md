# 공개 구간 대화 연결과 보행 검토

## 결론

공개 구간 이름과 선호 조건을 대화로 받고, 날짜·시각을 확인한 뒤 실제 시설·도로망 계산으로 연결했습니다. 집이나 임의 주소를 공개 끝점으로 대체하지 않습니다. 현재는 연동과 서귀포의 기존 두 공개 구간만 지원합니다.

## 사용법과 다음 할 일

`/app` → 지도 → ‘공개 구간을 대화로 찾기’에서 입력합니다.

1. `연동 공개 구간을 CCTV 위주로 3시에 갈게요`
2. 날짜를 물으면 `2026-11-20`
3. 오전·오후를 물으면 `오후`
4. 실제 후보와 확인한 출발 시각, 거리·시설 인접 비율을 표시합니다.

처음부터 `서귀포 공개 구간 2026-11-20 오후 9시`라고 입력해도 됩니다. 이후 `조명 위주로`, `최단 길`, `3시`처럼 조건을 바꿀 수 있습니다. 시각을 바꾸면 오전·오후를 다시 확인합니다. 날짜·시간을 확인해도 현재 계산에 시간별 밝기·통행량·시설 작동 상태가 반영되는 것은 아닙니다. 긴급·자료 출처·제보 요청은 날짜 질문보다 먼저 처리합니다.

화면 이동·페이지 종료·새로고침·초기화 시 대화 상태를 지웁니다. 서버에 대화별 위치 저장소를 만들지 않았습니다. 클라이언트가 임의로 보낸 위치 상태도 공개 구간의 끝점으로 사용하지 않습니다. 기본 합성 대화 시연은 별도로 유지됩니다.

다음으로 필요한 작업은 **현재 후보의 지도·로드뷰 대조**입니다. 화면에는 각 경로의 `보행 검토 0/전체 구간`을 표시합니다. 길의 시설 인접 비율이 높더라도 보도·횡단보도·출입 제한·장벽·계단·경사를 확인한 것은 아닙니다. 예전 경로의 지도 검토 기록은 끝점이 달라 이번 형상에 자동 적용하지 않았습니다.

## 검토표

`data/open/derived/yeondong_walk_review_UNREVIEWED.csv`와 `seogwipo_walk_review_UNREVIEWED.csv`에 경로별 선분 좌표, 지도 도로 링크, 공개 도로 태그와 빈 검토 칸이 있습니다. 모든 행은 ‘미확인’입니다. 공개 지도 태그는 현장 확인 기록이 아닙니다. 동일 선분이 두 후보에 반복될 수 있어 행수를 독립적인 길 개수로 세지 않습니다.

새 형상으로 표를 만들 때:

```bash
.venv/bin/python scripts/export_walk_review.py --region yeondong --output /tmp/yeondong-review.csv
```

기존 파일 덮어쓰기는 거부합니다. 확인 시 이미지 촬영일, 조회일, 판단 근거와 확인자를 남겨야 합니다. 표를 채워도 현재 서비스가 자동으로 검토 완료나 통행 가능으로 전환하지 않습니다. 오래된 이미지·판별 불가는 그대로 보류합니다. 이 표도 `data/open/` 아래에 있어 기존 배포 압축파일에서 제외됩니다.

## 구현 범위와 검증 기준

`POST /research/agent/conversation`은 기존 연구용 경로 계산기를 호출합니다. 결과·오류를 합성 경로로 대체하지 않으며, 자료가 없는 실행 환경은 503을 반환합니다. 반대 방향과 임의 주소는 지원 범위를 안내합니다. 범용 주소 검색·GPS·제주 전체 도로망·실시간 통행 검증은 후속 작업입니다.

검증 기준은 사용자가 정한 날짜·오전/오후 확인, 페이지 한정 위치 정책, 공개 끝점 범위, 기존 계산값 보존입니다. 테스트의 의미 판정은 명시한 예시 범위에 한정되며 자유로운 한국어 전반의 정확도를 뜻하지 않습니다. 지도 검토 완료 기대값은 없고 모든 선분이 미확인 상태여야 합니다. 시설 가중치나 안전 기준을 새로 확정하지 않았습니다.

자동 검사 결과: Python 281개 통과(의존성 경고 1개), 실제 Chromium의 320/390/430 화면 폭에서 5화면 검사 통과. 날짜→오전/오후→실제 경로, 화면 이동 후 상태 삭제, 실패 시 입력 유지, 기존 접수 흐름을 검사했습니다. 연동 검토표는 14행/고유 선분 13개, 서귀포는 7행/고유 선분 7개이며 전부 미확인입니다. 모델·외부 지도 요청은 하지 않았습니다.
