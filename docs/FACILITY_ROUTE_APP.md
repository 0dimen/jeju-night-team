# 공개 시설 데이터 기반 자동 경로 추천

## 결론

팀이 올린 `data/open/`을 읽어 **도로망에서 최단 경로와 시설 인접 구간을 선호하는 후보를 자동 탐색**하고 웹앱에 연결했습니다. 경로 화면 상단의 ‘공개 데이터로 길 찾기’를 사용합니다. 공개 구간 두 곳을 지원하는 연구 시연이며 임의 장소·집 주소 길찾기나 안전 보장 기능은 아닙니다.

CCTV는 사용자 전달 범위인 생활방범·교통단속·어린이보호·시설물관리4목적을 유지합니다. 기본 연구 원본은 더 최근인 행정안전부 표준 파일이고, 과거 데이터허브 원본도 선택해 비교할 수 있습니다. 두 원본을 합쳐 중복 계산하지 않습니다. 이 선택은 기본 합성 에이전트나 실제 서비스 승인 표시를 바꾸는 것이 아닙니다.

## 사용 방법

```bash
.venv/bin/python -m pip install -r requirements-base.txt
.venv/bin/python -m uvicorn agent.api:app --host 127.0.0.1 --port 8000
```

실행한 기기에서 `http://127.0.0.1:8000/app` → 지도 → 공개 데이터로 길 찾기 → 구간·우선 조건을 고르고 실행합니다. 기본 연구 설정은 조명15m·CCTV50m·시설 가중치4·최단 대비 거리 상한1.5배입니다. 화면에서 바꿀 수 있으며 사용자 시험으로 확정한 기준값이 아닙니다. 기존 합성 경로·자연어 대화는 아래 별도 영역에 유지합니다.

- 우선 조건: 최단 / CCTV / 조명 / 두 시설 함께.
- 자료 원본: 행정안전부 표준1,043행 중4목적937행 / 과거 데이터허브479행 중4목적473행.
- 새 연구API: `POST /research/routes/facilities`.
- 실제 좌표의 경로 도식과 카드 선택을 함께 표시합니다. 배경지도 타일·GPS·회전 안내는 연결하지 않았습니다.
- 동일한 길이면 하나만 표시하며 가짜 두 번째 후보를 만들지 않습니다. 시설이 더 많은 후보나 전역 최적의 우회 경로가 반드시 존재한다고 보장하지 않습니다.

## 계산 방법

팀이 준비한OSM 도로망에서 도로 조각의 시설 반경 원 합집합과 겹치는 길이를 계산합니다. 여러 시설의 반경이 겹쳐도 길이를 중복 합산하지 않습니다.

**도로 조각 비용 = 길이 × [1 + 조명 가중치×(1−조명 인접 비율) + CCTV 가중치×(1−CCTV 인접 비율)]**

선택한 시설의 가중치를 적용해 경로를 탐색합니다. 결과가 거리 상한을 넘으면 가중치를 절반씩 줄여 다시 찾으며, 한도 안의 대안을 못 찾으면 최단으로 돌아갑니다. 이는 연구용 탐색 방식이며 상한 안의 모든 경로를 열거해 시설 비율의 전역 최대를 구한 것은 아닙니다.

시설 개수가 아니라 **전체 경로 길이 중 인접 구간이 차지하는 비율**을 비교합니다. CCTV인접은 촬영·작동을, 조명 인접은 밝기·점등을 뜻하지 않습니다. 예상 시간은 거리÷분당75m(시속4.5km) 가정입니다.

## 실제 파일로 확인한 결과

행정안전부 표준 원본, CCTV우선 또는 두 시설 함께, 가중치4·거리 상한1.5배·반경15/50m 기준입니다.

| 구간 | 후보 | 거리 | 추정 시간 | CCTV 인접 | 조명 인접 |
|---|---|---:|---:|---:|---:|
| 연동 | 최단 | 352.4m | 4.70분 | 13.58% | 60.32% |
| 연동 | 시설 조건 우선 | 469.6m | 6.26분 | 47.26% | 65.11% |
| 서귀포 | 최단=시설 조건 우선 | 307.6m | 4.10분 | 70.18% | 62.34% |

연동 후보는117.2m 더 길며 CCTV33.68퍼센트포인트·조명4.79퍼센트포인트 높습니다. 이 값은 현재 입력·연구 설정의 결과입니다. 다른 반경·가중치·원본이면 달라질 수 있습니다. 서귀포에서 대안이 없는 것을 계산 실패나 CCTV없음으로 해석하지 않습니다. 두 지역은 수록 목적·범위가 달라 지역의 안전 수준을 서로 비교하지 않습니다.

연동 목적지는 ‘누웨마루’ 이름의 공중화장실 지도지점이며 거리 전체의 중심이나 정확한 입구가 아닙니다. 두 구간 모두 입력 끝점을 가장 가까운 도로 노드에 붙이고 그 차이를 응답에 표시합니다. 출발지·목적지를 임의로 바꿔 시설 우위가 나오는 길만 고르지 않았습니다.

## 자료·계산 검증

- 수정 가로등 사본은 원본 지문·행수·다른 열의 값·정확한 위경도 교환·수정 표시·16,155행 수가 수정 기록과 일치하는지 읽을 때 검사합니다. 원본을 고치거나 재저장하지 않습니다.
- CCTV 목적과 행 기준일, 자료 지문·선택행수·제외행수를 응답에 보존합니다. 다른 용도나 자료 없는 상태를 방범으로 재분류하지 않습니다.
- OSM중간 노드가 없으면 두 끝을 이어 가짜 도로를 만들지 않도록 보완했습니다. 명시적인 보행 일방통행도 반영합니다. 모든 도로 통행 규칙·장벽·계단·횡단·실제 폐쇄를 검증한 것은 아닙니다.
- 반경·가중치·상한·지역을 입력 검사합니다. 도로망 크기·파일 크기·끝점 연결 거리도 기술 지원 범위로 제한합니다. 사용자별 임의 위치는 받지 않습니다.
- 계산은 오프라인이고 모델·지도API를 호출하지 않습니다. 두 지역만 캐시하며 같은 계산기 내 설정 변경은 잠금으로 분리합니다.
- 원본이 없으면503으로 자료 연결 필요를 안내합니다. 합성값으로 조용히 대신하지 않습니다. `data/open/`은 웹 정적 경로로 제공하지 않습니다.

전체Python275개 통과(5.53초, 의존성 사용 중단 예정 경고1개). 실제Chromium320/390/430폭에서 공개자료 자동 탐색·도식/카드·동일 경로 하나 표시·자료 오류시 합성 대체 없음과 기존 대화·제보 흐름을 확인했습니다. 외부 요청0·JavaScript오류0. 실제GPS·센터·공개 배포·야간 작동은 검사하지 않았습니다.

## 배포 묶음에서 원본 제외

`data/open/`은Git에 남기고 `.gitattributes`의 `export-ignore`로 배포ZIP에서 제외합니다. 다음 도구는 **커밋한HEAD**를 묶고 ZIP안의 `data/open/`이0인지 검사합니다. 기존 파일은 덮어쓰지 않습니다.

```bash
.venv/bin/python scripts/build_runtime_archive.py --output /tmp/jeju-runtime.zip
```

전체 작업 폴더를 다른 도구로 그대로 업로드하면 이 제외 조건이 적용된다고 보장할 수 없습니다. 원본이 빠진 배포 코드만으로는 실제 경로 계산을 할 수 없으므로, 실행 서버에서 연구 데이터를 별도 보관·연결하려면 `JEJU_OPEN_DATA_DIR` 환경변수로 서버 전용 데이터 경로를 지정합니다. 원본을 브라우저 정적 자산으로 올리지 않습니다. 데이터가 연결되지 않았을 때 연구API는503을 반환하고 기본 합성 시연은 유지합니다.

공개 서비스용으로는 이용 조건·좌표 정밀도·도로 규칙·자료 갱신·개인정보·운영 권한을 별도 확인해야 합니다. 기존 `FileRouteEngine`의 실제 자료 확인 게이트는 바꾸지 않았습니다. 새 기능은 명시한 연구API·공개 구간 폼에 한정되며 기존 제보 게시 후 재분석 연결을 완료한 것은 아닙니다.
