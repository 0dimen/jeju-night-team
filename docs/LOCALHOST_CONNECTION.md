# 맥에서 라즈베리파이 웹앱 열기

## 결론

라즈베리파이에서 웹앱과 에이전트 API를 같은 서버로 실행하고, 맥에서는 SSH 터널로 접속합니다. 키는 라즈베리파이 서버가 읽으며 맥 브라우저에 입력하지 않습니다.

## 맥에서 접속

**라즈베리파이에 접속 중인 창과 별개로 맥의 새 터미널 창**을 엽니다. 다음 명령의 `사용자명@라즈베리파이주소`는 평소 SSH로 접속할 때 쓰는 대상으로 바꿉니다. SSH 별칭을 쓰고 있다면 그 별칭을 넣어도 됩니다.

```bash
ssh -N -L 18000:127.0.0.1:8000 사용자명@라즈베리파이주소
```

로그인한 뒤 별다른 출력 없이 기다리는 상태가 정상입니다. 이 창을 열어 둔 채 맥 브라우저에서 다음 주소를 엽니다.

**http://127.0.0.1:18000/app**

맥의 18000번을 라즈베리파이의 8000번에 연결합니다. 브라우저의 localhost는 현재 맥을 뜻하므로 라즈베리파이에 서버만 실행해 놓고 맥의 8000번을 열면 연결되지 않습니다.

끝낼 때 맥 터미널에서 Control+C로 터널을 닫습니다. 서버 종료와 터널 종료는 별개입니다. 맥의 18000번이 사용 중이라면 명령 맨 앞의 18000을 18001로 바꾸고 브라우저 주소도 18001로 바꿉니다.

## 화면에서 확인

1. 홈·지도 화면이 열리는지 확인합니다.
2. ‘공개 구간을 대화로 찾기’에서 `연동 공개 구간을 티맵으로 CCTV 위주로 3시에 갈게요`를 입력합니다.
3. 날짜에 `2026-11-20`, 오전/오후에 `오후`로 답합니다. TMAP 출처와 실제 후보를 확인합니다.
4. VWorld 버튼으로 지도 연결을 확인합니다.
5. 장소를 직접 선택하려면 별도 검색 영역에서 공개 장소부터 시험합니다. 검색 결과의 주소를 확인하고 날짜·24시간 시각을 입력합니다.

현재 화면과 API가 같은 주소로 연결되어 있습니다. 별도의 프론트 주소나 API 주소를 브라우저에 설정할 필요가 없습니다. 개인 위치·기록 정책과 미완료 기능은 [인수인계](AGENT_HANDOFF.md)를 따릅니다.

## 서버를 다시 실행해야 할 때

검토용 실행은 재부팅 후 자동으로 시작되지 않습니다. 서버가 종료되어 있으면 라즈베리파이의 팀 저장소에서 가상환경·서버 키를 준비한 뒤 실행합니다.

```bash
.venv/bin/python -m uvicorn agent.api:app --host 127.0.0.1 --port 8000 --no-access-log
```

환경변수 파일은 서버 시작 전에 불러와야 합니다. `VWORLD_API_KEY`·`TMAP_APP_KEY`를 사용하고 키 값은 출력하지 않습니다. 파일을 저장한 뒤 서버를 재시작하지 않으면 새 값이 반영되지 않습니다. 기본 에이전트는 규칙·문장 틀입니다.

현재 명령은 자동 재로딩을 켜지 않습니다. 기능 코드를 변경하면 서버를 종료하고 다시 실행해야 합니다. 같은 포트에 다른 서버가 있으면 임의로 종료하지 말고 담당 서버인지 확인합니다.

## 연결되지 않을 때

| 증상 | 확인할 것 |
|---|---|
| SSH 로그인 실패 | 평소 쓰던 사용자명·주소·SSH 키로 접속되는지 |
| 맥에서 주소가 열리지 않음 | 터널 창이 열려 있는지, 파이 서버가 실행 중인지 |
| 포트가 이미 사용 중 | 맥의 전달 포트를 18001 등으로 변경 |
| 화면은 열리지만 검색·경로 실패 | 서버 지도 키·한도·시설 자료 연결. 맥에 키를 넣는 방식이 아님 |
| 지도만 안 나옴 | VWorld 키·등록 도메인·제공사 연결. 계산 결과는 별도 |
| 새 코드가 반영되지 않음 | 서버 재시작·브라우저 새로고침, 데이터 변경 시 계산 자료 재생성 |

라즈베리파이 로컬 화면·API 연결과 맥의 SSH 터널 설정은 구분합니다. 맥에서 실제 접속 성공 여부는 사용자 기기에서 마지막으로 확인해야 합니다. 공개 배포와 운영 도메인 검증을 완료한 것은 아닙니다.
